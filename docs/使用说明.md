## 1. 安装与首次启动

### 选哪个安装包

| 包 | 适用 |
|---|---|
| `arm64-v8a` | 近几年的手机（绝大多数）|
| `armeabi-v7a` | 32 位老设备，标记 experimental，真机验证较少 |

> 更新方式：应用内可直接更新（设置 → 更新），也可手动下载覆盖安装。

### 首次启动会自动做两件事

1. **部署 Linux 环境**：proot + Ubuntu 24.04 rootfs **已内置在 APK 里**，不需要下载几百 MB 的 rootfs。
2. **按 MC 版本安装 Java**：1.8–1.16.5 → Java 8；1.17–1.20.4 → Java 17；1.20.5 及以上 → Java 21。

> 这两件事**全局共享**：装一次，之后所有实例复用，不需要重复等待。

### 会申请的权限，各自为了什么

| 权限 | 用途 |
|---|---|
| 通知 | 服务端运行时挂常驻通知保活；否则后台容易被系统杀掉 |
| 忽略电池优化 | 同上（首次启动会引导你去开）|
| 存储 | 导出日志 / 备份到任意目录、导入自己的服务端 jar |

### 需要联网的地方

首次部署环境、安装 Java、下载服务端核心 / 插件 / 模组、检查更新。**跑起来之后离线也能启动已有实例**。

## 2. 新建服务端（三步向导）

入口：底部「服务端」页 → 新建。

### 第 1 步：选核心

| 核心 | 适合 |
|---|---|
| 原版 Vanilla | 纯净体验，原汁原味 |
| Paper / Purpur / Spigot | 插件服，性能和生态最好（Purpur 可玩性参数最多）|
| Fabric / Forge / NeoForge | 模组服（Fabric 轻量、Forge/NeoForge 生态老牌）|
| 导入自己的 jar | 你已经有一个服务端核心文件 |

### 第 2 步：选版本与资源

- **版本**：按类型分档（正式版 / 快照版 / 远古测试版 / 远古预览版），可实时搜索。
- **内存**：给服务端的上限。手机建议留出余量 —— 分配过多会把系统本身挤到 OOM。
- **Java 版本**：默认按 MC 版本推断，可手动改。
- **核心构建 / 加载器版本**：如 Paper 的 build 号、Fabric 的 loader 版本，通常选默认即可。

### 第 3 步：配置与确认

- **端口**：新建时自动分配空闲端口（从 25565 起，跳过已被占用的）。
- **MOTD / 服务器属性**：这里填的会写进该实例的 `server.properties`。
- **EULA**：必须显式勾选同意（运行 Minecraft 服务端即代表你同意 Minecraft EULA）。
- 点确认后开始下载核心，过程中可看到进度。

## 3. 启动 / 停止 / 重启

### 状态含义

| 状态 | 含义 |
|---|---|
| 未启动 | 空闲，可启动 |
| 启动中 | 正在部署 / 装 Java / 下载或安装核心 |
| 首启 · 生成 eula.txt | 第一次启动，等服务端生成 eula.txt 后自动退出 |
| 已同意 EULA，正在重启 | 已把 eula 改为 true，自动再启动一次 |
| 运行中 | 服务端在跑 |
| 停止中 | 已发出停止，正在等它收尾（可能在保存世界）|
| 已停止 | 正常退出 |
| 启动失败 | 失败原因在「启动日志」里，控制台也会打印 |

### 停止：先优雅，要不要强杀由你决定

- 点「停止服务端」→ 只发送 `stop` 命令，然后**一直等服务器把世界存完**，不会自动强杀。
- 日志会在 15 秒、75 秒各提示一次：**要立即终止就再点一次「强制停止」**。
- 再点「强制停止」→ **先弹确认框**，确认后才：先发 SIGTERM 让它收尾，最多等 5 秒，之后强制结束。
- 代价：**没存完的部分可能会丢失**。所以只有确实卡死了才建议强杀。
- 正在弹确认框时如果服务器自己停好了，**这个提示会自动消失**（避免误点）。
- 重启按钮同理：会等它停稳再启动；超过两分钟还没停稳就取消本次启动并在控制台说明。

> 三个入口行为一致：首页主按钮、实例详情页按钮、服务端列表行的小按钮。

## 4. 控制台

底部「控制台」页。顶部有实例切换器，**每个实例有独立日志**。

### 怎么看

- **逐行着色**：INFO 常规、WARN 琥珀、ERROR 红、命令回显单独一色。
- **自动跟随**：新日志到达自动滚到底。手往上滑会**暂停跟随**，右下角出现「回到底部」。
- **`\r` 进度行原地刷新**：像 `Preparing spawn area: 55%` 这类不会刷爆屏幕。
- **同类刷屏折叠**：连续相同的行会被合并计数。

### 顶部占用行

```
CPU 12%（1.0核）· 内存 1.80G（45%）· 可用 3.2G
```

- **CPU**：整机占用率（已按核数折算），括号里是"用了几个核"。每秒刷新并做过平滑，不会乱跳。
- **内存**：服务端进程的实际占用 / 占整机比例。读不到会直接写「内存读不到（pid …）」，不会假装 0。
- **可用**：手机还剩多少可用内存（含可回收缓存）。系统判定低内存时会标出「（低内存）」。
- 数值用 `G` 是刻意的简写：整行必须挤在手机上的一行内，写全 "0.28 GB / 整机可用 3.20 GB" 会被截成「整机可…」。
- 这一行只在**运行中**出现；未启动时不占位。

### 输入命令

底部输入框（服务端运行中才可用）：`stop`、`op 玩家名`、`say 内容`、`whitelist add 玩家名`、`time set day`、`weather clear`… 服务端支持的命令都能用。

### 日志相关的几个细节

| 入口 | 作用 |
|---|---|
| 顶部「N 行」 | 点开「控制台统计」：内存里保留多少行、被丢了多少行、完整日志多大、放在哪 |
| 列表顶部「加载更早的日志」 | 内存只留最近 5 万行，更早的从磁盘日志文件回读 |
| 复制 / 保存日志 | 内容与屏幕所见一致（含清空后的状态）|
| 清空 | 同时清 UI 与内存缓冲，切走再回来不会"复活" |

## 5. 玩家管理

在实例详情页的「运行」区：先点一次刷新（发送 `list`），解析出在线玩家后按玩家名操作。

| 按钮 | 实际发出的命令 |
|---|---|
| 给予 OP | `op <玩家名>` |
| 取消 OP | `deop <玩家名>` |
| 踢出 | `kick <玩家名>` |
| 白名单 + | `whitelist add <玩家名>` |
| 白名单 − | `whitelist remove <玩家名>` |

> 注意：白名单要真正生效，`server.properties` 里的 `white-list` 需要为 `true`（可在「配置」里改）。

## 6. 实例详情（一页四块）

从「服务端」页点某个实例进入。**没有标签栏**，四块内容在同一页往下滚：

| 区块 | 内容 |
|---|---|
| 运行 | 状态胶囊 + 启停按钮、运行时长、**内存上限（点「修改内存分配」随时改，与创建时的滑块是同一个控件；内存是启动参数，重启后生效）**、在线人数、玩家管理、直达启动日志 |
| 配置 | `server.properties` 可视化编辑器（分组卡片），改完记得保存；也可以用**「用其他应用打开」交给系统或第三方编辑器**（保存后重启生效）。改端口等需要重启才生效 |
| 世界 | 世界目录与备份：创建 / 恢复 / 导入 / 导出。**恢复备份前必须先停服** |
| 附加 | 该实例的插件 / 模组列表与安装入口 |

> 「用其他应用打开」走系统的 `content://` 授权并**带写权限**，所以第三方编辑器能保存回去。
> 若你的实例目录被改到了应用无法共享的位置，会直接提示真实路径 —— 这时请用应用内编辑器改。

## 7. 插件与模组

## 8. 日志与排查

### 启动日志页

按实例汇总三类文件：崩溃报告（`crash-reports/`）、运行日志（`console-output.log`）、服务器日志（`latest.log`），可一键导出。

### 诊断页

应用自身的环境自检报告（部署状态、Java 版本、路径等）+ 应用日志。**反馈问题时优先给这个**。

后台拉起守护服务失败也会记进应用日志（如系统在后台拒绝启动前台服务）——排查「通知不见了 / 熄屏后服务端卡死」时先看这条线索。

### 控制台里"读不到 / 采样中"是什么意思

- `CPU 采样中…（…）`：还没认到服务端进程。括号里是诊断计数（扫了多少 pid、可读多少、选中了谁），截图即可定位。
- `内存 读不到（pid …）`：进程认到了，但读不到它的 `VmRSS`。这时不会显示成 0.00 GB 来误导你。
- 只要服务器在跑，这一行**一定会出现**，不会整行消失。

## 9. 备份与迁移

- 备份按实例隔离存放；可在实例的「世界」区创建 / 恢复，并导出到任意目录（SAF）。
- **恢复前先停服**：运行中恢复会同时动到世界文件，风险自负。
- 换手机 / 换目录：导出实例的备份或整个实例目录，在新设备上导入。

## 10. 设置

| 分组 | 可调 |
|---|---|
| 外观 | 主题风格（简洁面板 / 液态玻璃）、深浅色模式、配色来源、前景色、背景图 + 模糊 / 遮罩 |

| 存储 | 实例目录、占用情况 |
| 关于 | 版本、开源许可、致谢 |

## 11. 省电与保活

- 服务端运行期间有**常驻前台通知**：它同时是保活手段，也是"还在跑"的提醒，别手动划掉。
- 运行期间还持有**唤醒锁**：熄屏后 CPU 不休眠，服务端照常 tick，不会出现"没人动它也卡住"的熄屏挂起。代价是跑服期间**耗电与发热更高、手机不会深度休眠**，全部实例停止后即释放。
- 建议允许忽略电池优化，否则锁屏一段时间后**进程**仍可能被系统回收（唤醒锁防挂起，不防杀后台）。
- 手机上"慢"不等于"死"：本项目默认关闭了 MC 的看门狗强杀（`max-tick-time=-1`）、且默认不因空服自动暂停（`pause-when-empty-seconds=-1`），就是为了避免卡顿时被误判为崩溃。
- 内存吃紧时优先降低实例的分配内存，而不是加实例数量。

## 12. 已知限制

- **x86_64 模拟器跑不起来**：依赖 proot，而模拟器普遍用 ARM 翻译层，行为不可靠 —— 请用真机。
- **Forge / NeoForge 的 `--installServer` 尚未全面真机验证**：失败时控制台会打印安装器的完整输出，便于定位。
- **首次必须联网**（部署环境 + 装 Java + 下核心）；Spigot 走社区 CDN，没有官方哈希可比对。
- 32 位包（`armeabi-v7a`）真机验证较少。

## 常见问题

| 现象 | 先查什么 |
|---|---|
| 卡在「正在部署环境」 | 需要网络；看诊断页的环境自检报告。若之前换过存储位置，回到设置 → 存储确认目录可用 |
| Java 装不上 | 诊断页能看到安装输出；换网络/换镜像重试，或手动指定 Java 版本 |
| 启动失败 | 实例详情 → 「查看日志」看退出码与完整报错 |
| 端口被占用 | 「配置」里改 `server-port`（新建实例本就会自动挑空闲端口），改完重启 |
| 刚启动就"崩溃" | 多为卡顿被误判，本项目已默认关闭看门狗；若仍出现，看日志里的 tick 警告 |
| 服务端莫名其妙消失 | 多半是系统杀后台：确认已允许忽略电池优化、前台通知还在 |
| 内存显示 0.00 GB | 旧版本问题，已修（会显示真实值或「读不到」）；仍异常就截图那行诊断文字 |
| CPU 一直"采样中" | 旧版本问题，已修；现在是每秒采样并平滑显示 |
| 停不下来 / 想立刻停 | 一直等它存完最安全；确认卡死了再点一次「强制停止」并在弹窗里确认 |
| 手机发烫、耗电快 | 手机跑服务端本就吃资源：减少实例数 / 降低分配内存 / 空服时停掉 |
